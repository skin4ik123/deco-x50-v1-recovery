# Deco X50 v1: восстановление через старый HTTP recovery

[English](README.md)

Исследование восстановления обычного **TP-Link Deco X50 аппаратной версии v1**, который после обновления не загружается, но открывает U-Boot recovery на `http://192.168.0.1`.

Утилита создаёт экспериментальный кандидат на основе официальной **1.6.7 Build 25031412 Rel. 48241**. Меняется только неподписанное поле объявленной длины. Всё подписанное содержимое, включая систему, остаётся оригинальным.

**Статус на 01.11.2026: владелец подтвердил успешное восстановление.** В описанном случае X50 EU v1.0 с циклом загрузки восстановление с изменённой штатной прошивкой 1.6.7 завершилось успешно. Кандидат также прошёл исходный обработчик загрузчика на компьютере с заглушками вместо NAND. [Отчёт о восстановлении на устройстве](evidence/hardware_recovery_report.json). Результат относится к этому случаю; совместимость с другими аппаратными версиями и загрузчиками не установлена.

## Область применения

Исходный случай — X50 EU v1.0 со старым HTTP recovery. Установленный загрузчик устройства не считывался, совпадение с опубликованным кодом не доказано. Совместимость с v1.2, v1.3, v2, v3, PoE, Outdoor, 4G/5G и другими моделями не заявляется.

Это штатная TP-Link 1.6.7. Метод сохраняет RSA-подпись и не позволяет заменить систему на OpenWrt. Использование — только через страницу U-Boot recovery, не через приложение Deco или обычную веб-панель обновления.

В изученном коде записывается системный слот и меняется индекс загрузки. При `isManu=0` сохранённые настройки в `runtime_data` не стираются. Если причина цикла загрузки в этих данных, одна перепрошивка может не помочь. Другой загрузчик может иначе обработать изменённую длину. Использование кандидата остаётся экспериментом с риском потери работоспособности.

## Создать файл

Скачайте ZIP исходников этого репозитория и распакуйте либо клонируйте репозиторий. Нужен Python **3.9 или новее**. Из папки проекта:

```sh
python3 tools/make_recovery.py --download
```

В Windows вместо `python3` используйте `py -3`. Дополнительные Python-пакеты для создания файла не нужны.

Утилита скачает официальный ZIP по HTTPS, проверит SHA‑256 архива и исходного BIN, внесёт изменение и сохранит:

```text
artifacts/Deco_X50_V1_1.6.7_legacy_HTTP_recovery_EXPERIMENTAL.bin
```

Если скачивание не работает, возьмите [официальный ZIP 1.6.7](https://static.tp-link.com/upload/firmware/2025/202506/20250604/X50v1_1.6.7%20Build%2025031412%20Rel.%2048241.zip) вручную и укажите путь:

```sh
python3 tools/make_recovery.py --input "/путь/к/официальному.zip"
```

Подойдёт и извлечённый оригинальный BIN. Любой другой образ, повреждённый файл и уже изменённый кандидат отклоняются. Существующий выходной файл не перезаписывается. Утилита сама не подключается к Deco и ничего не прошивает.

| Проверка | Значение |
|---|---|
| Фактический размер | 37 363 379 байт — файл не обрезается |
| SHA‑256 кандидата | `0dd441b4dab6027591f0b1d13b4c63d7c820f5580473847a23730140e1e96370` |
| Новое поле объявленной длины | 33 560 596 (`0x02001814`) |
| Изменённые смещения от начала файла | 1, 2, 3; всё начиная со смещения 4 сохранено |

Проверить готовый файл:

```sh
python3 tools/make_recovery.py --check artifacts/Deco_X50_V1_1.6.7_legacy_HTTP_recovery_EXPERIMENTAL.bin
```

## Использование recovery

Сначала следуйте [официальной инструкции TP-Link](https://www.tp-link.com/ca/support/faq/2958/): для X50/X55 v1 указан первоначальный recovery через X55 1.2.2. Наш случай — файл принимался, но цикл загрузки сохранялся.

Экспериментальный BIN загружается через ту же страницу HTTP recovery: один Deco напрямую кабелем, ПК `192.168.0.2/24`, Reset при включении питания, страница `http://192.168.0.1`. Дождитесь сообщения о завершении записи. Подробности и ограничения — в [английской инструкции](README.md#recovery-procedure).

Когда штатная система запустилась, обычный сброс удаляет настройки: Reset на секунду, отпустить, подождать около двух минут. По [руководству X50](https://www.tp-link.com/uk/document/27326/?app=wifi-toolkit) пульсирующий синий означает готовность к настройке, зелёный — подключение. Красный индикатор сам по себе не означает успех.

## Почему это работает в модели

Старый обработчик проверяет размер по первым четырём байтам. Подпись проверяется по фактически принятому файлу начиная с `0x14`, а длина записи UBI берётся из подписанной таблицы. Поэтому изменение внешнего поля длины снимает старое ограничение, сохраняя подпись и весь системный образ.

UBI 1.6.7 занимает 37 355 520 байт и помещается в **предполагаемый** слот 42 MiB на стенде. Это подтверждает поведение исследованного кода, а не фактическую исправность NAND и загрузку конкретного Deco.

Четыре варианта с настоящим OpenWrt вместо штатного содержимого проверены локально: все отклонены по RSA до записи. Контрольный штатный кандидат принят. [Результаты OpenWrt](docs/openwrt.md).
